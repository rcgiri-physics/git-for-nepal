# 4. Code review with a checklist

## Hook
A reviewer says 'this is bad'. Is that helpful? What would help?

## Concept (unplugged or visual first)
Good review comment = **specific**, **kind**, **actionable**, **about the work not the person**. Practise rewriting unhelpful comments in pairs.

**Checklist**
- [ ] Does it do what the issue asks?
- [ ] Is it small enough to understand?
- [ ] Are names and messages clear?
- [ ] Does the page/program still run?
- [ ] Nothing private (names, passwords, marks) was added?

## PRIMM lab
1. Swap PRs with another pair. **Predict** the riskiest line before reading.
2. Read the diff, run the page. Fill the checklist.
3. Write 2 praise comments and 2 improvement comments.
4. Author replies and updates. Reviewer approves.
5. **Make:** improve the checklist for your team.

## Parsons practice
Match unhelpful comments to kind rewrites: 'ugly' → 'Could we use the school colour here?'.

## Exit ticket
1. Name three qualities of a good comment.
2. What should a reviewer check before approving?
3. *Misconception:* 'reviewing is only for experts.' True or false?

## Teacher notes
Reviewing teaches more than writing; grade the *quality of review comments*. Remind students that AI-generated code gets the same review as any other.
