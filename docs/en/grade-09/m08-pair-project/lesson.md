# 8. Pair project: Ward Facts

## Hook
The class will present to a visiting official: 'what do the ward numbers tell us?'

## Concept (unplugged or visual first)
Agree a **working agreement** in your pair: who owns which file, when you pull, how you name branches (`name/topic`), and how you review each other's commits.

## PRIMM lab
**Brief:** pairs maintain a Python script + SQL file answering 3 questions about the small ward dataset.
1. Clone the starter. Each partner creates a branch.
2. Each partner answers one question; merge via the shared remote.
3. Resolve at least one conflict honestly (the README is a good place).
4. Add a `CHANGELOG.md` entry and tag the result `v1.0` (`git tag v1.0`).
5. Present: show the graph, a diff, and the answers.

## Parsons practice
Order the pair routine: *pull · switch to your branch · work · commit · switch main · pull · merge · push*.

## Exit ticket
1. Which commit are you most proud of?
2. What did your pair agreement say?
3. *Check:* how can the teacher see who did what?

## Teacher notes
Rubric: ≥ 8 commits per pair; each partner ≥ 3; branch used and merged; ≥ 1 conflict resolved; README explains how to run; messages say what and why. Peer review: swap repos and write two comments on paper.
