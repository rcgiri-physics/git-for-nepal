# 1. The `final_final_v3` problem

## Hook (5 min)
Show this folder on the board:

```
essay.doc
essay_new.doc
essay_final.doc
essay_final_final.doc
essay_final_v3_REAL.doc
essay_final_v3_REAL_sir_checked.doc
```
Ask: *Which one should I hand in? Which one did Sir correct? What changed between `essay_new` and `essay_final`?*

## Unplugged (15 min): the folder game
In groups of 4, each group gets a printed paragraph. Round by round (2 minutes each) the group makes an edit and **saves a copy under a new name** on a fresh sheet. After 4 rounds, the teacher secretly asks: *"Go back to the version before the third edit."*

Discuss:
- How long did it take to find the right sheet?
- Could you tell *what* changed? *Why*? *When*?

## Think (PRIMM — Predict) (10 min)
Predict: if 30 students each keep 6 copies of 5 assignments, how many files is that? (900.) What if two people edit the same file?

## Key idea (5 min)
A good history records **what** changed, **when**, and **why**, and lets you go back. File names cannot do that. Git does.

## Exit ticket (5 min)
1. Name one problem with `final_final_v3`.
2. What three things should a history record?
3. *Misconception check:* "A bigger file name like `essay_final_v3_REAL` is a good version system." True or false? Why?
