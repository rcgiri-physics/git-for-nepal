# 7. Software process models and Git workflows

## Hook
Your syllabus has 'software process models'. Git workflows are the daily practice of those models.

## Concept (unplugged or visual first)
Compare on a timeline: **waterfall** (one big release), **iterative/agile** (small steps, frequent merges). Map: sprint ↔ milestone; backlog ↔ issues; increment ↔ release tag; code review ↔ quality gate.

## PRIMM lab
1. Sort the project's real history (this repo, last 20 commits and PRs) onto a timeline. Which model does it resemble?
2. **Predict** which model needs more branching, then count branches in the graph.
3. **Make:** one-page comparison table with examples from your Grade 10 team project.

## Parsons practice
Match term to Git artefact: backlog → issues; increment → tag; review → PR.

## Exit ticket
1. Which model uses small frequent releases?
2. What Git feature represents an increment?
3. *Misconception:* 'agile means no planning.'
