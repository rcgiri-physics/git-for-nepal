# 4. Your first PR — to this curriculum

## Hook
You will improve the very lessons you are learning from.

## Concept (unplugged or visual first)
Walk through the model used by `first-contributions`: fork → clone → branch → change → push → PR. Keep the change small (fix a typo, add a Nepali word to the glossary, improve an example).

## PRIMM lab
1. Fork this repo (tier 3) or the class copy on the LAN (tier 2).
2. Clone; `git switch -c fix/typo-...`.
3. Make one change; run `python tools/validate_frontmatter.py`.
4. Commit with a clear message; push; open a PR using the template.
5. **Investigate:** read the review comments; reply; push fixes.
6. **Make:** after the merge, add yourself to `CONTRIBUTORS` (the all-contributors file when set up).

## Parsons practice
Order: *fork · clone · branch · change · check · commit · push · PR · respond to review*.

## Exit ticket
1. What did the review change in your PR?
2. Why keep the first PR small?
3. *Misconception:* 'if my PR is closed, I failed.'

## Teacher notes
Maintainers must respond kindly within a week; add a `student-friendly` label. CSTA 3B-AP-20 (version control in a group project) is the international precedent for this module — verify wording before citing.
