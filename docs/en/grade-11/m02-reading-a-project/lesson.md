# 2. Reading a project: README, CONTRIBUTING, issues

## Hook
You join a new club. First you read the notice board. A repo's notice board is its README, CONTRIBUTING file and issues.

## Concept (unplugged or visual first)
Treasure hunt: a worksheet of questions to answer by reading `README.md`, `CONTRIBUTING.md`, `LICENSE`, the issues list and the last 10 commits of **this** repo.

## PRIMM lab
1. Open this repo on the server. Answer the 8 questions on the worksheet (How do I build the site? What label marks easy tasks? Who reviews Nepali text?).
2. **Predict** where a typo fix should go (branch? issue first?). Check `CONTRIBUTING.md`.
3. Read `git log` for how maintainers write messages.
4. **Make:** write a 5-line 'how to contribute' summary in your own words.

## Parsons practice
Order the first steps on a new project: *read README · read CONTRIBUTING · check issues · build/run · ask*.

## Exit ticket
1. Which file tells you how to contribute?
2. Where do you look for easy tasks?
3. *Misconception:* 'just send a PR without reading anything.'

## Teacher notes
Students under 18 should only contribute to projects the teacher has vetted (this repo and consented partners).
